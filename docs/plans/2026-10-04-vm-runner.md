# VM runners: one QEMU guest per thread, all traffic through cubed

Status: design for branch `feat/vm-runner`, 2026-10-04. Decided with the
maintainer; this document settles the interfaces and the order of work.
Reuses the proven spike in `spikes/l2-gateway/` (45 MB/s down on server1).

## Decisions

- A runner stops executing commands as its own account. It hosts one QEMU VM
  per active thread: Debian 13 genericcloud base image, a qcow2 overlay per
  thread, a cloud-init NoCloud seed. Linux/KVM is built and verified now;
  macOS QEMU+HVF gets code paths and docs and is verified later.
- The guest's only network is raw Ethernet frames: QEMU `-netdev dgram`
  (unix) → runner pump → Iroh QUIC datagrams (3-byte fragment header, guest
  MTU 1500) → `cube-gateway` next to cubed. The runner opens no socket for the
  guest other than that Iroh connection. No download exit this round.
- `cube-gateway` (new Rust package `packages/gateway`) is started and
  supervised by cubed. Per VM it runs a smoltcp LAN: DHCP, DNS, TCP
  termination. Egress is HTTP (80) and HTTPS (443) only; other TCP gets RST.
  HTTPS is TLS-intercepted with a per-installation CA. cubed decides every
  request (method, host, path, thread) in TypeScript over a local socket.
- Secrets: the guest sees placeholders (`GH_TOKEN=cube_ph_github_…`). The
  gateway substitutes the real value only when cubed's decision says so, and
  cubed says so only for the secret's hosts (github.com, api.github.com). Real
  values never enter the VM, the seed or the runner.
- Tools run in the guest over SSH. cubed reaches the guest's sshd through the
  gateway (the gateway dials 10.77.0.2:22 inside the LAN); nothing listens on
  the runner. The agent harness stays on cubed. `/workspace` lives on the VM
  disk.
- Replace, no fallback: runner protocol 3; same-UID shell execution, runner
  file operations and runner-side Git are removed.
- Kept invariants: lifetime lease locking, one writable owner per thread,
  stable invocation identity (one key → at most one effect), retained evidence
  (the VM disk of a changed or interrupted thread is kept, not deleted),
  runner journal reconciliation.
- Next round, seams only: macaroons, `.agents/setup` / resume, snapshots,
  download exit, more than one active VM per runner.

## Data flow

```
 browser ──HTTP/SSE──> cubed (Node) ─────────────── Pi Harness / Claude Code child
                         │  Workspace = VmWorkspace
                         │  ssh (OpenSSH client, ControlMaster)
                         │    ProxyCommand: cube-gateway dial --vm V --port 22
                         ▼
             run/gateway.sock (HTTP, 0600) ◀──spawn+lifeline── cubed
                         │                   run/egress.sock (HTTP, 0600) ◀── POST /v1/decide
                         ▼
                   cube-gateway ── per VM: smoltcp LAN 10.77.0.0/24
                         │           .1 gateway (DHCP, DNS, TCP termination, ssh dial)
                         │           .2 guest
                         │  Iroh, ALPN cube/l2/1, QUIC datagrams = fragmented frames
                         ▼
                    cube-runner ── pump: unix dgram socket <-> datagrams
                         │  control: Iroh ALPN cubeyard/node/1, protocol 3 (from cubed)
                         ▼
                 qemu-system-* -netdev dgram,unix   (one VM per active thread)
                         │
                   guest: sshd, cube-guest helper, /workspace, systemd
upstream:  cube-gateway ──TLS (system roots)──> public hosts, ports 80/443 only
```

A tool call: Pi `bash` → `VmWorkspace.exec(token, key, spec)` → lease check →
`ssh … cube-guest exec` with the operation JSON on stdin → guest helper
journals the key and starts a transient systemd unit → JSON state on stdout.
`operation()` long-polls `cube-guest get`. A web request from the agent:
guest `curl https://x` → DNS via .1 → TCP SYN to any IP:443 → gateway
terminates TLS with a leaf for the SNI → parses the HTTP/1.1 request →
`POST /v1/decide` → allowed: placeholders substituted, upstream connection to
the SNI host's public address → response streamed back.

## Identities, keys and state

| Item | Owner / location | Notes |
|---|---|---|
| Gateway Iroh key | `CUBED_STATE/gateway/iroh.key` 0600 | created by the gateway on first start |
| Installation CA | `CUBED_STATE/gateway/ca.key` 0600, `ca.pem` | P-256, CA:TRUE pathlen 0, 10 years; key never leaves this dir; a credential for backup purposes |
| vmId | thread record in `registry.sqlite` | 16 random hex chars, fixed at thread creation; cloud-init `instance-id` |
| MAC | derived: `02:` + first 5 bytes of sha256(vmId) | locally administered |
| SSH client key | `CUBED_STATE/threads/<id>/vm/id_ed25519` 0600 | per VM, `ssh-keygen`; public half in the seed |
| Guest host key | `CUBED_STATE/threads/<id>/vm/host_ed25519{,.pub}` 0600 | generated by cubed, pinned in `known_hosts`, private half in the seed |
| Placeholders | thread record | `cube_ph_<name>_<22 base62>`, per VM, not secret |
| Frame token | memory only (cubed → runner, gateway) | 32 random bytes hex, minted per `vm.start` |
| Runner VM journal | runner `state/journal.db` | VM records, epochs, base image hash |
| Guest op journal | guest `/var/lib/cube/ops/` | command and write keys, results, output |

The seed holds the guest host private key and public material only. The
runner can read the VM disk anyway, so the host key adds no trust; it holds no
credential to anything outside the VM.

## Runner protocol 3

ALPN stays `cubeyard/node/1`; framing unchanged (4-byte length + JSON, hello
then one request). `protocolVersion` and `minimumProtocolVersion` are 3; a
protocol-2 peer gets `INCOMPATIBLE_PROTOCOL` before any mutation.
Capabilities: `node.status`, `vm.allocate`, `vm.start`, `vm.stop`,
`vm.inspect`, `vm.release`. Hello `limits`: `maxFrameBytes`,
`requestTimeoutMs`, `maxVcpus`, `maxMemoryMiB`, `maxDiskGiB`, `maxSeedBytes`
(64 KiB), `maxActiveVms` (1). Hello also reports `platform`
(`linux-x86_64`, `macos-aarch64`) and `baseImageSha256`.

Every request carries `threadId` and `vmId`; every mutation carries `epoch`
and is fenced per thread exactly as today (`LEASE_STALE` below the newest
seen). All are idempotent by content: the same request returns the current
record, a different `diskGiB`/seed for an existing VM is `CONFLICT`.

| Method | Request | Effect |
|---|---|---|
| `vm.allocate` | `diskGiB` | journal `allocating`; `qemu-img create -f qcow2 -F qcow2 -b ../../images/<sha256>.qcow2` (relative, so a restored state directory may move); `allocated`. `diskGiB` must cover the base image's virtual size and stay within `maxDiskGiB`. `CAPACITY_EXCEEDED` when `maxActiveVms` are active; another active VM of the same thread is `CONFLICT`. A failed `qemu-img` removes the directory and forgets the record (`IO_ERROR` with the reason), so the same request can be retried. Repeating it for a released VM returns the `released` record: a vmId is never reused |
| `vm.start` | `vcpus`, `memoryMiB`, `mac`, `seed {metaData, userData, networkConfig}`, `gateway {peer, frameToken}` | first start records `vcpus`, `memoryMiB`, `mac` and the seed's sha256, all fixed for the VM's life (a different value is `CONFLICT`); writes the FAT seed; `starting`; spawns QEMU; `running` once QMP answers `query-name` with the vmId. The request waits up to 3 s for that and otherwise answers `starting` (QMP is awaited for 60 s more, then QEMU is killed). A QEMU that exits early gives the record back in `stopped`/`allocated` with `error` (the tail of `qemu.log`), not an error response. On a starting/running VM: replaces gateway peer/token and closes the old frame connection, nothing else. Allowed from `allocated`/`stopped`; other states are `CONFLICT` |
| `vm.stop` | — | asynchronous (the request bound is 5 s): `stopping`, then QMP `system_powerdown`, 30 s, QMP `quit`, 10 s, SIGKILL of the QEMU this process spawned; `stopped` when QEMU has exited; disk kept. A forced stop sets `interrupted`. Poll `vm.inspect` |
| `vm.inspect` | — (read-only) | record + `consoleTail` (last 16 KiB of serial log); `NOT_FOUND` for an unknown vmId |
| `vm.release` | `retain: bool` | `releasing`; a live VM is stopped first (asynchronously, as `vm.stop`); `retain:false` deletes the VM directory → `released`; `retain:true` → `retained`. A VM whose record is `interrupted` and a `failed` one are always retained |

Record: `{vmId, threadId, state, interrupted, error?, diskBytes, seedSha256?,
startedAt?}`; `state` ∈ `allocating allocated starting running stopping
stopped releasing released retained failed`. `running` means QEMU is alive,
not that the guest is ready; readiness is cubed's concern. `interrupted`
means the last stop was not clean (runner died, or the guest had to be
killed); the next start that reaches `running` clears it. A record belonging
to another thread is `CONFLICT`. `diskBytes` is allocated bytes of the
overlay; `startedAt` is unix milliseconds.

`node.status` reports `lifecycle` (`ready`, `draining`, `faulted`,
`recoveryRequired`), `draining`, `error?`, `activeVms`, `runningVms`,
`maxActiveVms`, `retainedVms`, `retainedBytes`. Error responses are
`{code, message, completionUnknown}` (no `operationId` any more). A
well-formed request naming a method protocol 3 does not have is `UNSUPPORTED`
(after hello; before hello every non-hello request is `INVALID_REQUEST`).

Reconciliation on `runner-serve` start: `allocating`/`releasing` → `failed`
(tree kept); `starting`/`running`/`stopping` → connect to the recorded QMP
socket; if it answers `query-name` with the vmId send `quit`; record
`stopped`, `interrupted: true`. The runner never signals a PID it did not
spawn in this process. On Linux QEMU gets `PR_SET_PDEATHSIG(SIGKILL)` (and
`-sandbox on,obsolete=deny,elevateprivileges=deny,spawn=deny,resourcecontrol=deny`).
Drain (SIGTERM, Ctrl-C): refuse `vm.start`/`vm.allocate`, `vm.stop` every
running VM, exit. A stopped VM is booted again by cubed's next `vm.start`;
the guest marks unfinished operations interrupted on boot.

QEMU (x86_64): `-machine q35,accel=kvm -cpu host -smp N -m M -nodefaults
-no-user-config -vga std -display none -name guest=<vmId> -serial file:console.log
-qmp unix:qmp.sock,server=on,wait=off -drive if=virtio,file=disk.qcow2,discard=unmap
-drive if=virtio,file=seed.img,format=raw,readonly=on -netdev
dgram,id=n0,local.type=unix,local.path=qemu-net.sock,remote.type=unix,remote.path=net.sock
-device virtio-net-pci,netdev=n0,mac=<mac> -device virtio-rng-pci`.
`-vga std` is required: with `-nodefaults` and no display adapter the Debian
13 genericcloud image reboots in a loop right after GRUB (seen on server1,
QEMU 8.2). macOS: `qemu-system-aarch64 -machine virt,accel=hvf -cpu host -bios
<edk2-aarch64-code.fd>`, arm64 genericcloud image, no `-sandbox`, no PDEATHSIG
(QMP reconcile covers it). Unverified this round.

Seed: a FAT image labelled `CIDATA` written in Rust with the `fatfs` crate
(`user-data`, `meta-data`, `network-config`), so the runner needs no
genisoimage/hdiutil. VM directories are `state/vms/<n>/` with a short index
`<n>` (unix socket paths stay under 104 bytes).

Runner init (`init` with a home, `runner-init --key K --state S` for services):
`cube-runner init --home H --image PATH --allow-peer CONTROL
--node-id … --thread-id … --env … [--qemu PATH] [--firmware PATH]
[--max-vcpus 4 --max-memory-mib 8192 --max-disk-gib 64]`. It copies the base
image to `state/images/<sha256>.qcow2` (0400) and records the hash; serve
re-checks size and identity and refuses a missing `/dev/kvm` (Linux) or
`kern.hv_support` (macOS) and QEMU older than 7.2. `--workspace` is gone. A
protocol-3 runner needs a new state directory; old state is left untouched
and opening it fails with "this state belongs to a protocol-2 runner" (journal
`user_version` 3 vs 1). The base image must be qcow2 without a backing file;
it is re-hashed at every start. `qemu-img` is taken from QEMU's directory or
`PATH` and recorded at init. `runner-acknowledge-recovery` takes `--key` and
`--state` only. A `call --request <json>` subcommand sends one protocol-3
request with the control key (operators, the live smoke).

### Frame channel `cube/l2/1`

The runner endpoint also accepts ALPN `cube/l2/1`. The gateway dials the
runner (cubed already knows every runner's peer and address; the runner keeps
only accepting). Authorization is per VM and comes from the authenticated
control peer: the latest accepted `vm.start` names `gateway.peer` and
`frameToken` (runner stores sha256 of the token). The gateway opens one
bi-stream and sends `{vmId, threadId, frameToken}` (length-prefixed JSON); the
runner checks peer, a running VM with that id, and the token in constant time,
then answers `{ok: true, mtu: 1500}`; otherwise `{ok: false, mtu, error}` and
close. A peer that is no VM's gateway is closed with `UNAUTHORIZED` before
any byte is read. Datagrams
in both directions are Ethernet frames split with the spike's header (u16
frame id, index/count nibbles). One frame connection per VM; a newly
authenticated one replaces the old. `vm.start` with a newer epoch rotates the
token, so a stale cubed/gateway pair loses the channel; `vm.stop`/`vm.release`
close it. Frames are dropped while no connection exists. `Fragmenter`,
`Reassembler`, the ALPN and the hello types live in
`cube_node_transport::l2`, shared by runner and gateway.

## Gateway interfaces

Binary `cube-gateway`:

- `serve --state DIR --control SOCK --decide SOCK --network loopback|direct|relay [--listen ADDR]`.
  Exits when stdin reaches EOF (lifeline from cubed). After the control socket
  listens it prints one JSON line on stdout:
  `{"ready":true,"version":…,"peer":…,"caSha256":…}`.
- `dial --control SOCK --vm ID --port 22`: splices stdio to an upgraded dial
  stream (OpenSSH `ProxyCommand`).
- `--version`. A `test-hooks` cargo feature (never in release builds) adds
  `--test-upstream HOST=ADDR` and `--test-upstream-ca FILE` so tests can map
  hosts to local fake upstreams.

Control API, HTTP/1.1 on `CUBED_STATE/run/gateway.sock` (0600, served by the
gateway, used only by cubed):

| Route | Body / result |
|---|---|
| `GET /v1/hello` | `{version, peer, network, caPem, caSha256}` |
| `PUT /v1/vms/{vmId}` | `{threadId, runner: {peer, network, address?}, frameToken, mac}` → status. Creates the LAN and keeps dialling the runner (backoff 0.5–10 s) until deleted; a changed token/runner replaces the connection and keeps the LAN; a changed `threadId`/`mac` is `409`; a runner wider than the gateway's network mode is `400` |
| `DELETE /v1/vms/{vmId}` | drops flows, LAN and connection → 204 |
| `GET /v1/vms/{vmId}` | `{link: connecting\|up\|down, leased, guestIp, flows, rxBytes, txBytes, lastError}` |
| `GET /v1/vms` | all attached VMs (cubed reconciles after either side restarts) |
| `POST /v1/vms/{vmId}/dial?port=22` | `Upgrade: cube-tcp` → `101` then raw bytes to guest:22 from 10.77.0.1; `403` for any other port; `404` for an unattached VM; `502` when the guest refuses or times out (10 s) |

Decision API, HTTP/1.1 on `CUBED_STATE/run/egress.sock` (0600, served by
cubed, called by the gateway once per HTTP request, keep-alive):

```
POST /v1/decide
{"vmId","threadId","scheme":"https","method":"GET","host":"api.github.com","port":443,
 "path":"/user","placeholders":["cube_ph_github_…"]}
-> {"allow":true,"substitute":{"cube_ph_github_…":"<real value>"}}
-> {"allow":false,"reason":"…"}
```

No answer within 5 s, a malformed answer or a socket error is a deny. A deny
returns `403` to the guest with `x-cube-denied: <reason>`.

LAN behaviour per VM (from the spike, made persistent per VM rather than per
connection): 10.77.0.0/24, gateway .1, guest .2, DHCP with MTU 1500, router
and DNS .1. DNS: A queries answered from the host resolver (TTL 30) with
public addresses only (private answers would leak the host's network and are
refused anyway), single-label names NXDOMAIN, AAAA empty NOERROR, others
NOTIMP. TCP: SYN to port 80/443 on any address is
terminated; anything else gets RST; frames from a MAC other than the attached
one are dropped; UDP other than DHCP/DNS is dropped; no
IPv6. Limits: 256 flows per VM, 256 KiB buffers per flow, 10 min idle, 64 KiB
request head.

HTTP handling: the gateway serves TLS with a leaf for the ClientHello SNI
(rcgen, P-256, 24 h, in-memory cache) and offers ALPN `http/1.1` only. No SNI
→ close. Requests are parsed with hyper; `Host` must match the SNI (else 421).
`CONNECT` and `Upgrade` are refused this round. Port 80 uses `Host`, whose
port must be 80 (else 421). Each guest connection keeps one upstream
connection for keep-alive. The
upstream host is the SNI/Host name, never the IP the guest dialled; it is
resolved by the gateway and every address must be public unicast (no
loopback, RFC 1918, link-local, CGNAT, multicast, ULA, IPv4-mapped forms,
`0.0.0.0/8`, documentation ranges) — enforced in Rust after resolution,
independent of policy, so the guest cannot reach cubed, the LAN or a
metadata service. Upstream TLS verifies against the system roots
(`rustls-native-certs`). Bodies stream in both directions and are never
modified.

Secret injection: the gateway scans request header values for
`cube_ph_[a-z0-9]+_[A-Za-z0-9]{22}` not followed by another alphanumeric
character, including inside a decoded
`Authorization: Basic` value, and lists the matches in `placeholders`. It
substitutes only what `substitute` returns (re-encoding Basic) and only over
HTTPS; a decision that returns substitutions for plain HTTP is answered with
`403` and nothing is sent. A placeholder cubed allows but does not substitute is forwarded
unchanged; it is worthless outside this gateway. The gateway keeps no secret
beyond the request it is serving.

## cubed side

Policy (`egress-policy.ts`, TypeScript, one `EgressPolicy.decide(context)`):
this round allows every public host and method except `CONNECT`, logs denies
at info and decisions at debug (path truncated to 256 bytes), and maps
placeholders: a placeholder must belong to the asking VM, the scheme must be
https and the host must be in the secret's list, else deny with a reason.
Secret sources: `github` → `GithubAuth`'s `gh auth token` (cached 60 s; not
connected means no substitution and GitHub answers 401). The macaroon seam is
`decide`'s context; nothing else depends on the policy's shape.

Gateway supervision (`gateway.ts`): cubed locates the binary (`CUBED_GATEWAY`,
else `<release>/bin/cube-gateway`, else `target/{release,debug}/cube-gateway`
in a source checkout; none → VM threads fail with "gateway unavailable", no
fallback), spawns it with a stdin lifeline before `Conversations.boot()`, waits
for the ready line, restarts it with backoff 1–30 s and re-`PUT`s every active
VM after a restart. The network mode is the widest among enrolled runner
configs (relay > direct > loopback). Socket paths reuse cubed's existing
short-path handling for `workspace.sock`.

### Tool execution over SSH: OpenSSH client

cubed uses the system OpenSSH client, not an npm SSH library:

- the same mature implementation on both ends, no new npm dependency and no
  JavaScript SSH stack in cubed;
- `ControlMaster` gives one multiplexed connection per VM, so a tool call or
  poll is a cheap channel, and `ServerAliveInterval` detects a dead path;
- host keys are pinned exactly (cubed generated them), with no TOFU.

The costs (a process per call, parsing exit codes) are bounded by the guest
helper's JSON protocol; exit status 255 with no helper output means the
transport failed. Command line:

```
ssh -F none -o BatchMode=yes -o IdentitiesOnly=yes -i vm/id_ed25519
    -o UserKnownHostsFile=vm/known_hosts -o StrictHostKeyChecking=yes
    -o HostKeyAlias=cube-vm-<vmId>
    -o ProxyCommand='<cube-gateway> dial --control <run>/gateway.sock --vm <vmId> --port 22'
    -o ControlMaster=auto -o ControlPath=<run>/ssh/<12 hex> -o ControlPersist=120
    -o ServerAliveInterval=10 -o ServerAliveCountMax=3 -o ConnectTimeout=20
    -o LogLevel=ERROR root@cube-vm <op>
```

The guest's `authorized_keys` entry is
`restrict,command="/usr/local/sbin/cube-guest ssh" <key>`: the key can only
run the helper, which dispatches on `SSH_ORIGINAL_COMMAND`.

### Guest helper `cube-guest`

Python 3 standard library only (Debian genericcloud ships python3 for
cloud-init), shipped as text in the seed, ~500 lines, in
`packages/server/guest/cube-guest.py`. Protocol: one JSON header line on
stdin, optional raw body; one JSON line on stdout, optional raw body. Limits
equal protocol 2's (8 KiB command, 4 KiB path, 600 s, 256 KiB output in
64 KiB pages, 512 KiB read/write, 100,000 records).

| Op | Input | Output |
|---|---|---|
| `hello` | — | `{version, ready, limits, epoch}`; `ready` once cloud-init is done |
| `exec` | `{id, epoch, command, cwd, timeoutMs, outputLimit}` | operation state |
| `get` | `{id, cursor?, waitMs? ≤ 20000}` | operation state (long poll) |
| `cancel` | `{id, epoch}` | state right after `systemctl kill --signal=SIGKILL` |
| `read` | `{path, offset?, limit?}` | `{size, eof, sha256, offset, length}` + body |
| `write` | `{id, epoch, path, expectedSha?, createParents?, length}` + body | `{sha256, size}`, journaled |
| `stat` | `{path}` | `{kind, size, mode, modifiedMs, sha256?}` |

Operation states and error codes are protocol 2's (`Accepted`, `Running`,
`Succeeded`, `Failed`, `Interrupted`, `Written`, `Unknown`; `CONFLICT`,
`LEASE_STALE`, `PRECONDITION_FAILED`, `NOT_FOUND`, `INVALID_REQUEST`, …), so
`workspace.ts`'s `operation()` mapping is reused unchanged.

Journal: `/var/lib/cube/ops/<id>/` created with `mkdir` (create-only) holding
the canonical request hash; same id + same hash returns the record, different
hash is `CONFLICT`; records are fsynced and never deleted. Epochs:
`/var/lib/cube/epoch`, monotonic, older is `LEASE_STALE`. A command runs as
user `agent` in a transient unit: `systemd-run --unit=cube-op-<id>
-p User=agent -p WorkingDirectory=/workspace/<cwd> -p RuntimeMaxSec=<timeout>
-p ExecStopPost=/usr/local/sbin/cube-guest finish <id>` running a small
wrapper that keeps the first `outputLimit` bytes of combined output and drains
the rest. `ExecStopPost` writes the terminal result atomically from
`$SERVICE_RESULT`/`$EXIT_CODE`/`$EXIT_STATUS`. Cancel and timeout kill the
whole cgroup. `cube-guest-recover.service` (before `ssh.service`) marks every
record without a result `Interrupted { completionUnknown: true }` at boot;
transient units do not survive a reboot, so this is exact. Paths are relative
to `/workspace`; absolute, `..` and NUL are refused and the resolved path must
stay beneath `/workspace`. Writes go to a temp file, fsync, rename, directory
fsync. The VM is the isolation boundary, so path checks are contract, not
security. Environment: `HOME=/home/agent`, standard `PATH`, `LANG=C.UTF-8` and
`/etc/cube/env` (placeholders, CA variables).

### VmWorkspace

`VmWorkspace implements Workspace` over a `GuestTransport` (`call(op, header,
body?) → {header, body}`) and the existing `LeaseStore`. Lease semantics are
unchanged. Operation ids stay `ws-sha256([binding, vmId, key])`. A transport
failure on a read is `NODE_UNAVAILABLE`; on a mutation it is
`COMPLETION_UNKNOWN` (the key can be inspected). `capabilities()` and
`limits()` come from `hello`. `durable-agent.ts`, `codemode.ts`,
`workspace-env.ts`, `workspace-http.ts`, `claude-agent.ts` and the Claude Code
mod keep calling `Workspace`; only tool descriptions change ("thread VM").
Pi's `cube.runner` document binding adds `vmId`.

### Thread lifecycle in cubed (`vm.ts`)

- Create: registry stores `vm: {vmId, placeholders}`; keys generated in
  `threads/<id>/vm/`.
- Activate (`ensureWorkspace`, also at boot): `vm.inspect`; `vm.allocate` if
  absent; `vm.start` with a new frame token and the gateway peer;
  `PUT /v1/vms/{vmId}`; wait for `leased`, then SSH `hello` until `ready`
  (300 s budget, first boot installs packages); provision once under key
  `cube:provision`: an `exec` of a cubed-built script that, per repository,
  `git init`, `git fetch <url> refs/heads/<branch>` (credentials via the
  placeholder), verifies `<oid>^{commit}` and checks it out detached — primary
  in `/workspace`, references in `/repos/<name>`; empty projects get an empty
  `/workspace`. Then `markWorkspaceAvailable`. Registry `workspaceState`
  `allocating` covers boot and provisioning.
- cubed restart: VMs keep running; activation re-runs `vm.start` (rotates the
  token), re-attaches and Pi reattaches to running commands by key.
- Gateway restart: guest TCP flows reset; SSH masters reconnect; running
  commands survive in their systemd units.
- Runner restart: VM stopped and `interrupted`; activation boots it again from
  the same disk; interrupted keys report `interrupted`.
- Archive: run the release check (`exec` key `cube:release-check:<epoch>`:
  every checkout clean at its pinned OID, no extra commits, branches or
  stashes, `/workspace` empty for empty projects, no running operation);
  `vm.release {retain: !clean}`; unreachable guest → `retain: true`.
  `DELETE /v1/vms/{vmId}`, delete the SSH keys only when released.

## Guest image and seed

Base: `debian-13-genericcloud-{amd64,arm64}.qcow2`, supplied by the operator
at runner init (the runner downloads nothing). Seed (built by cubed in
`vm-seed.ts`, written by the runner):

- `meta-data`: `instance-id: <vmId>`, `local-hostname: cube-<vmId[0..8]>`.
- `network-config`: v2, DHCP on the first NIC.

## CA handling

The gateway creates the CA on first start and never rotates it on its own.
cubed reads the certificate through `GET /v1/hello` and embeds it in every
seed. Leaves are minted per SNI in memory. Deleting `CUBED_STATE/gateway/ca.*`
makes a new CA for new VMs; existing VMs would distrust it (rotation is a
later concern). Docs name the CA key as an installation credential.

## Risks and open points

- First boot runs `apt-get install` through the gateway; the known 30 s
  `apt-get update` stall (also under QEMU NAT) makes thread start slow until
  snapshots.
- TLS interception breaks clients that pin certificates or bundle their own
  roots and ignore the variables above; such tools need explicit handling.
- HTTP/2, WebSocket and `CONNECT` are refused this round.
- macOS HVF, `-netdev dgram` on macOS and arm64 UEFI boot are unverified.
- Power-loss durability of the guest journal depends on QEMU flush semantics
  and is not tested, as before.
